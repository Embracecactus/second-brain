# RV1126B 运动相机项目

## 项目概述

基于 Rockchip RV1126B SoC 的运动相机开发项目，包含自定义硬件设计（双 MIPI CSI 摄像头、MIPI DSI 屏幕、IMU、立体声麦克风、WiFi/BT、电池管理）和配套软件栈。项目同时开发了 **BoardRoot** 框架 —— 一个可组合的 Ubuntu/Debian rootfs 构建系统，首个参考目标即为 RV1126B SportCam。

## 技术栈

| 层次 | 技术 |
|------|------|
| SoC | Rockchip RV1126B (ARM Cortex-A7) |
| 内核 | Linux 6.1 (Rockchip BSP) |
| Bootloader | U-Boot + Rockchip MiniLoader (rkbin) |
| 根文件系统 | Ubuntu 22.04 Jammy arm64 (debootstrap) |
| 构建系统 | Buildroot 2025.02.3 + BoardRoot (自研) |
| 交叉编译器 | GCC 10.3 aarch64-none-linux-gnu (SDK prebuilts) |
| 多媒体 | GStreamer / Rockit → MPP + RGA + RKAIQ ISP |
| AI 推理 | RKNPU2 + RKNN Toolkit2 + RKNN-LLM |
| AMP 通信 | OpenAMP / rpmsg-lite |
| 应用框架 | CMake 交叉编译 (C 语言) |
| 组件管理 | 自定义 YAML manifest + shell 脚本管道 |
| 版本控制 | Git + SDK patches (generate/apply/revert) |

## 硬件架构

### 核心外设

| 模块 | 型号 | 接口 |
|------|------|------|
| 主摄 | IMX415 (4K) | MIPI CSI0 4-lane + I2C3 |
| 辅摄 | 待定 | MIPI CSI1 4-lane + I2C4 |
| 屏幕 | 3.1 寸 | MIPI DSI 2-lane + I2C5 触摸 |
| IMU | LSM6DSOWTR (6轴) | I2C/SPI |
| 麦克风 | 2x ICS-43432 立体声 | SAI (I2S) |
| WiFi/BT | MOD_BL_M8723DU1 | USB 2.0 Host |
| Flash | W25Q128JVPIQ (16MB) | FSPI (SPI NOR) |
| SD 卡 | — | SDMMC |
| USB | Type-C | USB 3.0 Device + 下载 |
| 电量计 | BQ27441 | I2C |
| 充电 | TP4056 + LTC4412 Oring + TPS61022 升压 | — |
| 降压 | SY8113BADC 5.5V→3.3V | MOSFET 控制各外设上电 |

### MIPI CSI 通道分配

- **MIPI CSI0 (RX0)**: IMX415, 4-lane, ISP0, 主摄 4K30 录像
- **MIPI CSI1 (RX1)**: 待定, 4-lane 预留, ISP1, 辅摄 HDR/AI 扩展
- 双 ISP (ISP0/ISP1) + 双 MIPI CSI PHY 硬件基础

### 电源架构

```
电池 → TP4056 充电 → LTC4412IS6 Oring 切换 → TPS61022RWUR 升压 → SY8113BADC 3.3V
                                                                              ↓
                                                                   MOSFET 控制各外设上电时序
```

## 关键设计决策

### BoardRoot 根文件系统组合模型

```text
rootfs = distro + platform + board + product + profile + components
```

层次关注点分离：发行版、平台、板级、产品、构建变体、可复用组件各自独立配置，通过 YAML manifest 组合。支持两种模式：
- **copy 模式**: 早期 bring-up，直接从 SDK 拷贝文件
- **deb/package 模式**: 长期维护，通过 APT 包管理

### SDK Patch 管理工作流

SDK 不提交到主仓库，通过 `sdk.conf` 指定路径。所有 SDK 修改以 patch 形式管理：

```bash
# 修改 SDK 后生成 patch
./scripts/generate-patches.sh

# 首次搭建：clone SDK + 应用所有 patch
./scripts/setup-sdk.sh

# 应用/还原 patch
./scripts/apply-patches.sh
./scripts/revert-patches.sh
```

Patch 命名规范: `NNNN-repo-name.patch`，按 SDK 子仓库分别管理。

### 交叉编译工具链配置

CMake toolchain file 自动从 `sdk.conf` 读取 SDK 路径，定位 GCC 10.3 交叉编译器：

```cmake
# toolchain-rv1126b.cmake 核心逻辑
get_filename_component(PROJECT_ROOT "${CMAKE_CURRENT_LIST_DIR}/../.." ABSOLUTE)
# 从 sdk.conf 解析 SDK_ROOT
set(TOOLCHAIN_PREFIX "${SDK_ROOT}/prebuilts/gcc/linux-x86/aarch64/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu")
set(CMAKE_C_COMPILER "${TOOLCHAIN_PREFIX}/bin/aarch64-none-linux-gnu-gcc")
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)  # 不搜索目标程序
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)    # 只搜索目标库
```

### 日志系统

rkipc 风格的日志宏，支持 minilogger 和 stderr 两种后端，运行时级别控制：

```c
// log.h — 条件编译 + 运行时级别控制
extern int rkipc_log_level;   // LOG_LEVEL_ERROR/WARN/INFO/DEBUG/VERBOSE
extern int enable_minilog;    // 0=stderr, 1=minilogger

#define LOG_INFO(format, ...)                                              \
    do {                                                                   \
        if (rkipc_log_level < LOG_LEVEL_INFO) break;                       \
        if (enable_minilog)                                                \
            minilog_info("[%s][%s]:" format, LOG_TAG, __FUNCTION__, ...);  \
        else                                                               \
            fprintf(stderr, "[%s][%s]:" format, LOG_TAG, __FUNCTION__, ...); \
    } while (0)
```

### 系统配置命名空间 (BoardRoot)

`system:` 命名空间统一管理 hostname、APT 源、用户、fstab、网络配置，与 legacy 字段保持向后兼容：

```yaml
system:
  hostname: rv1126b
  apt:
    mirror: https://ports.ubuntu.com/ubuntu-ports/
  users:
    root:
      password: 123456
    ubuntu:
      password: 123456
      groups: adm,sudo,video,render,input,audio,plugdev,dialout
      shell: /bin/bash
  fstab:
    - source: LABEL=rootfs
      mountpoint: /
      type: ext4
      options: defaults,noatime
  network:
    renderer: networkd
    interfaces:
      - name: eth0
        dhcp4: true
```

## 构建/运行指令

### 运动相机应用编译

```bash
cd rv1126bsportCam/app/myapp
mkdir build && cd build
cmake -DCMAKE_TOOLCHAIN_FILE=../toolchain-rv1126b.cmake ..
make
```

### SDK 固件构建

```bash
cd sdk
./build.sh lunch           # 选择板级配置
./build.sh kernel          # 编译内核
./build.sh rootfs          # 编译 rootfs
./build.sh firmware        # 打包固件
./rkflash.sh all           # 烧录到设备
```

### BoardRoot 构建 Ubuntu rootfs

```bash
cd BoardRoot
make validate                                    # 运行 28 个离线验证
./build.sh list                                  # 列出可用预设
./build.sh use rockchip-rv1126b-debug            # 选择预设
./build.sh plan                                  # 查看构建计划
./build.sh dry-run                               # 模拟构建（无需 sudo）
./build.sh resolve                               # 合并本地 SDK 路径
./build.sh rootfs                                # 完整构建
```

### BoardRoot 组件结构规范

每个组件遵循统一结构：

```text
components/<name>/
├── component.yaml    # 元数据 (name, mode, vendor, source, install, validate)
├── install.sh        # 安装脚本 (--rootfs, --vendor-sdk, --config)
└── validate.sh       # 可选的安装后验证
```

## 关键学习点

1. **Rockchip SDK 构建链路**: U-Boot → MiniLoader → Kernel → rootfs → firmware 打包，`build.sh` 是统一入口
2. **设备树 overlay 机制**: 通过 overlay 文件实现硬件配置的模块化，避免直接修改 SDK 内核 DTS
3. **ISP 双通道**: RV1126B 有 ISP0/ISP1 双通道，支持双摄同时工作，为 HDR 和 AI 扩展提供硬件基础
4. **rootfs 组合设计**: BoardRoot 的 `distro + platform + board + product + profile + components` 模型将关注点清晰分离
5. **YAML 解析零依赖**: `manifest.sh` 使用 awk 解析 YAML，避免引入外部依赖，保持构建环境最小化
6. **Patch 优先于 Fork**: SDK 修改以 patch 管理而非 fork，便于 SDK 版本升级时迁移
7. **Copy 模式过渡**: 早期 bring-up 使用 copy 模式快速验证，长期转向 deb/package 模式维护
