# Allwinner H5 Crust Firmware 项目分析

## 项目概述

Crust Firmware 是一个开源的系统控制处理器（SCP）固件，专为 Allwinner sunxi 系列 SoC 设计，运行在 AR100（OpenRISC 1000）微控制器上。它通过实现深度睡眠状态来管理电源，可将设备功耗降低 80% 以上，是替代 Allwinner 专有闭源固件的社区驱动方案。

本项目目录（`/home/lijian/project/h5`）包含 Crust 固件源码及多份深度分析文档，涵盖架构设计、自定义固件开发指南、多固件动态切换方案等内容。

## 技术栈

- **目标处理器**: Allwinner AR100（OpenRISC 1000 / or1k 架构，32 位 RISC）
- **编程语言**: C11 + OpenRISC 汇编
- **构建系统**: GNU Make + Kconfig（复用 Linux 内核的配置系统）
- **交叉编译器**: `or1k-linux-musl-gcc`（GCC 9.1.0+ 官方支持）
- **通信协议**: ARM SCPI（System Control Processor Interface）
- **固件加载器**: U-Boot v2021.01-rc1+ / ARM Trusted Firmware v2.3+
- **目标平台**: Allwinner A23, A33, A64, A83T, H3, H5, H6
- **许可证**: BSD-3-Clause OR GPL-2.0-only

## 系统架构

### 整体分层

```
Linux Kernel / ATF (主操作系统 + 安全固件)
        | SCPI 协议
Crust 固件核心 (system.c / scpi.c / device.c)
        |
硬件抽象层 HAL (CSS / DRAM / CCU / GPIO / IRQ)
        |
平台特定代码 (A64 / H5 / H6 / H3 / A23 / A83T)
        |
启动和运行时 (start.S / runtime.S / exception.c)
        |
AR100 (OpenRISC 1000) 硬件 + SRAM A2
```

### 系统状态机（核心设计）

Crust 的核心是一个 11 状态的有限状态机，管理整个系统生命周期：

```c
enum {
    SS_AWAKE      = 0x0,  // 主 OS 运行
    SS_BOOT       = 0x1,  // SoC 复位后首次启动
    SS_REBOOT     = 0x2,  // PMIC 重启
    SS_SHUTDOWN   = 0x3,  // 清醒 -> 关机过渡
    SS_SUSPEND    = 0x4,  // 清醒 -> 睡眠过渡
    SS_OFF        = 0x5,  // 关机，RAM 丢失
    SS_ASLEEP     = 0x6,  // 睡眠，RAM 保持
    SS_PRE_RESET  = 0x7,  // 复位过渡
    SS_PRE_RESUME = 0x8,  // 恢复过渡
    SS_RESET      = 0x9,  // 从关机复位到启动
    SS_RESUME     = 0xa,  // 从睡眠恢复到清醒
};
```

**设计亮点**：状态值 +2 即可推进到序列中的下一步，配对状态共享代码，减少重复。`SS_BOOT` 必须非零，确保 `system_state` 存储在 `.data` 段，仅在 SoC 复位后重新初始化（而非固件重启后）。

### 硬件平台关键参数

| 平台 | SRAM A2 大小 | SCPI | CPU 核心 | DRAM 挂起 | PMIC |
|------|-------------|------|----------|----------|------|
| H5 | 32KB | Yes | Yes | Yes | N/A |
| A64 | 32KB | Yes | Yes | Yes | Yes |
| H6 | 96KB | Yes | Yes | Yes | Yes |
| H3 | - | Yes | Yes | Yes | N/A |

### 固件启动流程

```assembly
; arch/or1k/start.S - 汇编启动入口
start:
    l.mfspr r2, r0, SPR_SYS_PPC_ADDR   ; 保存异常向量地址
    ; 清空指令缓存 (256 行 x 16 字节块)
    ; 启用指令缓存 (ICE bit)
    ; 清空 .bss 段
    l.jal system_state_machine           ; 跳转到 C 状态机
```

### 内存布局（SRAM A2）

```
0x00000: .text (固件代码)        ~40KB
0x0A000: .rodata (只读数据)      ~10KB
0x0C800: .data (数据段)          ~5KB
0x0DC00: .bss (未初始化数据)     ~5KB
0x0F000: SCPI 共享内存           1KB
0x0F400: 栈空间                  ~2KB
0x0FC00: 堆空间                  ~1KB
```

## 关键设计决策

### 1. 深度睡眠实现机制

Crust 通过多层断电实现深度睡眠：

- **CPU 断电**：关闭所有 Cortex-A53 核心，断开集群供电（节省 ~1500mW）
- **DRAM 自刷新**：DRAM 芯片内部自行刷新数据，控制器可断电（节省 ~250mW）
- **外设断电**：关闭非必要外设和时钟（节省 ~200mW）
- **时钟门控**：禁用所有 PLL，仅保留必要振荡器（节省 ~50mW）

总功耗从 ~2550mW 降至 ~70mW，节省约 97%。

### 2. SCPI 双客户端模型

```c
enum {
    SCPI_CLIENT_EL3 = 0,  // ATF (安全 EL3) - 处理安全电源状态转换
    SCPI_CLIENT_EL2 = 1,  // Linux (非安全 EL2) - 常规电源管理请求
};
```

### 3. 挂起深度选择

```c
enum {
    SD_NONE    = 0,  // 不进入深度睡眠
    SD_OSC24M  = 1,  // 保持 24MHz 振荡器
    SD_AVCC    = 2,  // 保持 AVCC 电源
    SD_VDD_SYS = 3,  // 保持 VDD-SYS 电源
    SD_DRAM    = 4,  // 完全深度睡眠，DRAM 自刷新
};
```

系统根据当前状态和唤醒源需求智能选择挂起深度。

### 4. 驱动框架统一接口

```c
struct device_ops {
    int  (*init)(struct device *dev);
    int  (*probe)(struct device *dev);
    void (*suspend)(struct device *dev);
    void (*resume)(struct device *dev);
};
```

所有驱动（msgbox, serial, clock, dram, pmic, gpio, watchdog, irq）共享此接口，实现硬件抽象。

### 5. 二进制转换处理字节序

```makefile
$(TGT)/scp.bin: $(TGT)/scp.elf
    $(OBJCOPY) -O binary -S --reverse-bytes 4 $< $@
```

`--reverse-bytes 4` 处理 AR100 大端模式与小端系统的差异。

## 构建指南

### 环境准备

```bash
# 下载交叉编译工具链
wget http://musl.cc/or1k-linux-musl-cross.tgz
tar xzf or1k-linux-musl-cross.tgz
export PATH=$PWD/or1k-linux-musl-cross/bin:$PATH
export CROSS_COMPILE=or1k-linux-musl-
```

### 编译固件

```bash
# 选择开发板配置（如 Orange Pi PC2）
make orangepi_pc2_defconfig

# 或手动配置
make nconfig

# 编译
make -j$(nproc)

# 输出文件
ls build/scp/scp.bin   # 最终固件镜像
ls build/scp/scp.elf   # ELF 格式（含调试符号）
```

### 构建产物

- `scp.bin` - 二进制固件，由 U-Boot/ATF 加载到 SRAM
- `scp.elf` - ELF 格式，用于 GDB 调试
- `scp.map` - 链接映射，分析内存布局

## 自定义固件开发方案

项目中包含三份关于 AR100 自定义固件的详细指南，描述了 Crust 之外的开发路径：

### 方案对比

| 方案 | 适用场景 | 电源管理 | 灵活性 |
|------|---------|---------|--------|
| **Crust 固件** | 移动设备、电池供电 | 完整支持（97% 功耗节省） | 低（固定功能） |
| **完全自定义固件** | 持续供电设备、原型开发 | 不支持 | 高（完全控制 AR100） |
| **Crust 驱动层复用 + 多固件切换** | 需要复用成熟驱动 | 不使用状态机/SCPI | 中高（多固件运行时切换） |

### 动态加载技术原理

Linux 通过内核模块控制 AR100：

```c
// 1. 映射硬件
sram_a2_base = ioremap_wc(0x00010000, 0x18000);  // SRAM A2
cpucfg_base  = ioremap(0x01700000, 0x1000);       // CPUCFG

// 2. 停止 AR100
writel(readl(cpucfg_base + 0x0108) | BIT(0), cpucfg_base + 0x0108);

// 3. 写入固件
memcpy_toio(sram_a2_base, firmware_data, firmware_size);

// 4. 启动 AR100（从 0x00000000 重新执行）
writel(readl(cpucfg_base + 0x0108) & ~BIT(0), cpucfg_base + 0x0108);
```

### 自定义固件工具链要求

- 编译器: `or1k-linux-musl-gcc`
- 编译选项: `-nostdlib -ffreestanding -Os`
- 链接脚本: 指定 SRAM A2 内存布局（起始地址 0x00000000）
- 二进制转换: `objcopy -O binary -S --reverse-bytes 4`

## 关键学习要点

### 1. SCP 固件设计模式

Crust 展示了嵌入式 SCP 固件的标准设计模式：状态机驱动、分层架构、HAL 抽象、标准协议通信。这种模式适用于任何需要独立协处理器管理电源或低功耗任务的场景。

### 2. DRAM 自刷新技术

DRAM 自刷新是深度睡眠的关键：控制器发出自刷新命令后，DRAM 芯片内部自行维持刷新周期（每 7.8us），控制器和主 CPU 均可断电。恢复时需先恢复时钟，再退出自刷新，最后恢复主设备访问。

### 3. SRAM 内存管理

AR100 仅能访问 SRAM（32-96KB），无法访问 DRAM。这要求固件代码极度精简（`-Os` 优化），避免大缓冲区，使用紧凑的数据结构。链接脚本需要精确控制各段的布局以最大化利用有限空间。

### 4. 跨平台固件复用

Crust 通过统一的设备接口和平台特定的头文件实现 7 个 SoC 的支持。每个平台仅需提供 `memory.h`（内存布局）和 `devices.h`（设备地址）两个头文件，驱动代码完全共享。

### 5. Crust 与自定义固件的权衡

AR100 同一时间只能运行一份固件。选择 Crust 意味着获得完整的电源管理能力（电池设备的关键需求），但牺牲了自定义灵活性。选择自定义固件则相反。这是一个不可兼得的架构约束。
