# 抖音视频爬虫与文案风格分析

## 项目概述

`douyin-creator-skills` 是一套面向抖音内容创作者的 Claude Code Skill 工具包，核心功能是实现从抖音账号视频批量下载到口播文案风格量化分析的完整自动化管线。该项目通过 F2 框架批量下载抖音账号全部视频，利用 FFmpeg 提取音频后调用 faster-whisper 进行 GPU 加速的语音转录（ASR），再对转录文本执行多维度的风格量化分析——包括篇幅分布、高频短语、句式特征、内容类型分类和话题聚类。分析结果可自动生成专属的文案写作 Skill，使 Claude Code 能够模仿特定博主的语气、节奏和结构风格生成口播文案。项目还包含 Manim 技术动画生成能力，可根据文案内容自动生成用于视频叠加的动画素材。整个系统基于 273 篇真实口播文案（136 个 SRT 原始字幕 + 170 个 ASR 转录）的统计分析成果构建，形成了从数据采集、语音转录、风格分析到内容生成的端到端工作流。

## 架构与设计

### 整体管线架构

该项目采用分阶段管线（Pipeline）设计，共 8 个 Phase，每个 Phase 独立执行、可断点续跑：

```
Phase 0: 初始化（创建工作目录）
    |
Phase 1: 前置环境检查（Python/F2/FFmpeg/faster-whisper/GPU）
    |
Phase 2: Cookie 管理（检查→验证→引导刷新）
    |
Phase 3: F2 批量下载视频（全部作品 + 描述文案）
    |
Phase 4: FFmpeg 批量提取音频（16kHz 单声道 WAV）
    |
Phase 5: faster-whisper 批量语音转录（GPU large-v3 → CPU medium 降级链）
    |
Phase 6: SRT 字幕转换（可选，处理已有字幕文件）
    |
Phase 7: 风格量化分析（篇幅/短语/句式/类型/话题）
    |
Phase 8: 自动生成专属写作 Skill
```

### 三层 Skill 架构

系统由三个 Skill 协作构成完整的内容生产链：

1. `/douyin-crawler` — 数据采集与分析层：负责视频爬取、音频转录和风格量化
2. `/zhuzhuxu-writer` — 文案生成层：基于分析结果生成符合特定风格的口播文案
3. `/video-enhancer` — 视觉增强层：根据文案内容生成 Manim 技术动画

### 输出目录结构

```
{工作目录}/
  videos/              # F2 下载的原始视频（MP4 + desc.txt）
  audio/               # FFmpeg 提取的 16kHz WAV 音频
  transcripts/         # faster-whisper ASR 转录文本
  srt_originals/       # SRT 字幕转换后的纯文本
  analysis/
    style_analysis.json        # 完整分析数据（JSON）
    style_analysis_report.md   # 可读分析报告
```

## 核心知识点

### 1. F2 视频下载与 Cookie 管理

F2 是抖音视频批量下载的核心工具，需要登录态 Cookie 才能正常工作。Cookie 存储在 `~/.f2/app.yaml` 配置文件中。

**Cookie 验证命令：**

```bash
f2 dy -m post -u "{用户URL}" -o 1 -p /tmp/cookie_test --max-tasks 1
```

**批量下载命令：**

```bash
f2 dy -m post \
  -u "{用户URL}" \
  -i all \
  -p "{工作目录}/videos" \
  --max-tasks 5
```

F2 自动跳过已下载文件，支持断点续传。每个视频生成 `*.mp4` 视频文件和 `*_desc.txt` 描述文案。

### 2. FFmpeg 音频提取

从 MP4 视频中提取 16kHz 单声道 PCM WAV 音频，这是 Whisper 模型的标准输入格式：

```bash
ffmpeg -i "$f" -vn -acodec pcm_s16le -ar 16000 -ac 1 "$OUT" -y
```

关键参数说明：
- `-vn`：跳过视频流
- `-acodec pcm_s16le`：16-bit PCM 编码
- `-ar 16000`：采样率 16kHz
- `-ac 1`：单声道

### 3. faster-whisper GPU 转录与降级链

转录脚本实现了三级模型降级策略，确保在各种硬件环境下都能运行：

```python
# 降级链：large-v3 GPU → medium GPU → medium CPU
if device == "cuda":
    try:
        model = WhisperModel("large-v3", device="cuda", compute_type="float16")
    except:
        try:
            model = WhisperModel("medium", device="cuda", compute_type="float16")
        except:
            model = WhisperModel("medium", device="cpu", compute_type="int8")
```

**CUDA 库路径探测**（WSL2 环境关键步骤）：

```bash
find ~/.local/lib -name "libcublas.so*" 2>/dev/null
export LD_LIBRARY_PATH={找到的路径}:$LD_LIBRARY_PATH
```

**性能预估：**
- GPU (large-v3)：每个视频约 10-20 秒，100 个视频约 20-30 分钟
- CPU (medium)：每个视频约 2-5 分钟，100 个视频约 3-5 小时

### 4. SRT 字幕转换

将 SRT 格式字幕文件转换为纯文本，核心逻辑是剥离序号、时间戳和 HTML 标签：

```python
def srt_to_text(srt_path: str) -> str:
    with open(srt_path, "r", encoding="utf-8-sig") as f:
        content = f.read()
    lines = content.strip().split("\n")
    text_lines = []
    for line in lines:
        line = line.strip()
        if re.match(r"^\d+$", line):       # 跳过序号
            continue
        if re.match(r"^\d{2}:\d{2}:\d{2}", line):  # 跳过时间戳
            continue
        if not line:
            continue
        line = re.sub(r"<[^>]+>", "", line)  # 移除 HTML 标签
        text_lines.append(line)
    return "".join(text_lines)
```

### 5. 风格量化分析引擎

`analyze_style.py` 是整个系统的核心分析模块，执行 8 个维度的文本分析：

**分析维度：**

| 维度 | 方法 | 输出 |
|------|------|------|
| 篇幅分布 | 中文字符计数 | avg/median/min/max |
| 高频短语 | 正则匹配 30+ 预设短语 | phrase_frequency |
| 句式特征 | 问号/感叹号/句长统计 | question_count, avg_sentence_chars |
| 内容类型 | 关键词匹配分类 | content_type_distribution |
| 高频双字词 | bigram 统计 | top_bigrams (Top 30) |
| 话题频率 | 预设话题词计数 | topic_frequency |
| 开场白模式 | 提取每篇前 40 字 | sample_openings |
| 结尾模式 | 提取每篇末 50 字 | sample_closings |

**中文字符计数核心函数：**

```python
def count_chinese_chars(text: str) -> int:
    return len(re.findall(r"[一-鿿]", text))
```

**内容类型分类关键词映射：**

### 6. 口播文案风格要素（基于 273 篇真实文案统计）

**节奏控制指标：**

| 指标 | 数值 | 来源 |
|------|------|------|
| 平均字数 | 385 字 | 273 篇均值 |
| 语速 | 200-250 字/分钟 | 短视频标准 |
| 每步字数 | 50-100 字 | 教程类 |
| 步骤数 | 3-4 步 | 80% 教程使用 |
| 平均句长 | 10-25 字 | 口语化要求 |

**高频口语词 Top 12（按使用频率）：**

| 词汇 | 使用场景 | 出现率 |
|------|---------|--------|
| 今天 | 开场引入 | 65% |
| 然后 | 句间过渡 | 56% |
| 分享 | 引出内容 | 35% |
| 其实 | 解释前铺垫 | 34% |
| 特别 | 强调感受 | 20% |
| 最近 | 开场时间锚 | 25% |
| 就像 | 类比过渡 | 18% |
| 所以说 | 总结归纳 | 12% |
| 是不是 | 互动反问 | 10% |
| 说白了 | 简化概念 | 高频 |
| 简单说 | 概念引入 | 中频 |
| 哈喽大家好 | 视频问候开场 | 中频 |

**人设推断规则：**

- 高频"其实"/"说白了" → 真诚直率性格
- 高频自嘲类词汇 → 幽默自嘲性格
- 高频"我们"/"一起" → 共同学习视角
- 开场白用"最近在学"而非"今天教大家" → 学习者身份而非权威教学

### 7. Manim 技术动画生成

`video-enhancer` Skill 包含 6 种动画类型模板：

| 动画类型 | 适用场景 | Manim 核心类 |
|---------|---------|-------------|
| 概念对比 | 单vs多、旧vs新 | RoundedRectangle + Text |
| 流程步骤 | 三步法、工作流 | VGroup.arrange + Arrow |
| 架构图 | 系统设计、模块关系 | 多层 RoundedRectangle |
| 数据结构 | 链表、树、图 | Circle + Arrow |
| 图表对比 | 性能对比、数据展示 | BarChart |
| 代码高亮 | 代码演示、语法讲解 | Code + SurroundingRectangle |

**Neon Tech 配色方案：**

```python
BG = "#0A0A0A"        # 深黑背景
PRIMARY = "#00F5FF"   # 青色
SECONDARY = "#FF00FF" # 紫色
ACCENT = "#39FF14"    # 绿色
MONO = "WenQuanYi Zen Hei"  # 中文字体
```

**关键规则 — 文字必须跟随框一起排列：**

```python
# 正确做法：每个元素是框+文字的 VGroup 组合
tasks = VGroup()
for i in range(5):
    rect = RoundedRectangle(...)
    label = Text(...)
    label.move_to(rect)           # 文字先居中到框内
    task_group = VGroup(rect, label)  # 组合成一个单元
    tasks.add(task_group)
tasks.arrange(RIGHT, buff=0.3)    # 整体排列
```

### 8. 写作 Skill 自动生成规范

从 `style_analysis.json` 自动生成专属写作 Skill，输出结构：

```
~/.claude/skills/{昵称}-writer/
  SKILL.md              # 主 Skill 文件（含 9 个必含章节）
  references/
    vocabulary.md       # 个人词表（8 个章节）
    style-examples.md   # 8-10 篇代表性真实文案
    templates.md        # 5 种内容类型填空模板
```

**SKILL.md 必含 9 个章节：**

1. 人设与语气（从 sample_openings + 高频口语词推断）
2. 内容类型与结构模板（按 content_type_distribution 比例列出）
3. 开场白库（从 sample_openings 提取 8-12 种模式）
4. 结尾库（从 sample_closings 提取 5-8 种模式）
5. 类比技法（从 transcripts 中提取含"像"/"好比"的句子）
6. 节奏控制（基于 avg_chars, avg_sentence_chars）
7. 标签策略（基于 topic_frequency）
8. 备选标题策略（6 种策略）
9. 质量检查清单（10 项自检）

### 故障排查速查

| 错误 | 原因 | 修复 |
|------|------|------|
| `f2: command not found` | F2 未安装 | `pip3 install -U f2` |
| F2 返回 HTTP 403 | Cookie 过期 | 刷新 Cookie（F12 → Network） |
| `libcublas.so.* not found` | CUDA 库路径未设置 | `export LD_LIBRARY_PATH=...` |
| CUDA out of memory | large-v3 需 ~3GB VRAM | 脚本自动降级到 medium |
| 中文字体显示方块 | Manim 字体缺失 | 使用 `WenQuanYi Zen Hei` |

## 关键学习收获

1. **端到端管线设计**：将视频下载、音频处理、语音转录、文本分析串联为自动化管线，每个阶段独立可断点，体现了工程化的 Pipeline 设计思想。

2. **GPU/CPU 优雅降级**：faster-whisper 转录脚本实现了 large-v3 GPU → medium GPU → medium CPU 的三级降级策略，确保在各种硬件环境下都能运行，是容错设计的良好实践。

3. **风格量化分析方法**：通过高频短语统计、bigram 分析、内容类型关键词匹配、开场/结尾模式提取等多维度量化手段，将主观的"文风"转化为可测量的数据指标，为 AI 生成提供了精确的风格锚点。

4. **从数据到 Skill 的闭环**：分析结果不仅输出报告，还能自动生成 Claude Code Skill（含词表、范例、模板），实现了从数据采集到内容生产能力的闭环转化。

5. **口播文案的结构化模板**：将 273 篇真实文案归纳为 5 种内容类型模板（技术教程、工具分享、学习日记、项目展示、踩坑记录），每种模板包含段落结构、字数范围、填空占位符和过渡语，是结构化写作的方法论。

6. **Manim 动画的框内文字排列规则**：在 Manim 中创建带文字的形状时，必须将 Text 和 Shape 组合为单个 VGroup 后再 arrange，否则 arrange() 会分别移动它们导致位置错乱。

7. **Cookie 管理的工程化处理**：通过自动检查 → 验证有效性 → 引导用户刷新的三步流程，解决了爬虫工具中常见的登录态管理问题。
